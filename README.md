# Industrial SDLC Skill

> 工业级软件开发流程规范 Skill，专为大型项目设计。

## ⚠️ 资源消耗警告

**本 Skill 专为大型项目设计，执行过程将消耗大量资源：**

- **Token 消耗**：单次完整流程可能消耗 500K-2M+ tokens
- **API 成本**：技术调研、多轮方案审查优化、完整设计文档产出将产生显著费用
- **时间成本**：完整 SDLC 流程可能需要数小时到数天

**使用前请确认您有足够的 API 额度/预算支持。**

## 概述

Industrial SDLC 是一个强制遵循"先设计后编码"原则的 Skill，适用于从零开始构建大型软件项目。它将用户需求转化为可执行的项目开发计划，杜绝无文档直接写代码的行为。

### 第一性原则

> **以全面、完全、优越性能实现项目需求为唯一目标。**
> - 禁止任何形式的偷懒
> - 禁止最小实现/MVP 思维
> - 禁止"先简单后升级"策略
> - **不需要考虑资源消耗和 token 消耗**

## 核心特性

### 1. 交互式需求澄清
- 主动提问确认需求边界
- 砍掉伪需求，明确 Out of Scope
- 产出完整 PRD（产品需求文档）

### 2. 多轮技术搜索与方案优化
- 三轮深度技术搜索（探索→验证→边界场景）
- 至少两轮严格审查优化
- 8 维度审查标准（完整性、性能、安全、可扩展等）

### 3. 阶段强制停止
- 每个阶段完成后必须 STOP
- 明确展示产出物，等待用户确认
- 禁止智能体单方面推进

### 4. 禁止偷懒规则
- 全局禁止 TODO/FIXME 占位符
- 禁止"先简单后升级"
- 所有代码必须一次性达到生产就绪状态

## SDLC 流程

```
Phase 0: 需求澄清与 PRD 产出
  ├── 交互式需求澄清
  ├── 多轮深度技术搜索
  ├── 方案自主审查优化（至少两轮）
  └── 输出 PRD + 最终技术方案
  ⏸️ STOP - 等待用户确认

Phase 1: 系统设计
  ├── 系统架构设计
  ├── 数据库设计（完整表结构）
  ├── API 接口文档（所有接口）
  └── Tech Spec
  ⏸️ STOP - 等待用户评审

Phase 2: 开发执行
  ├── Git Flow 分支管理
  ├── 按模块开发 + 单元测试
  └── Code Review
  ️ STOP - 等待用户验收

Phase 3: 测试验证
  ├── 冒烟测试 → 接口自动化 → 性能压测 → 安全测试
  └── UAT 用户验收
  ⏸️ STOP - 等待最终验收
```

## 安装

将 `SKILL.md` 放置于以下路径之一：

- **Claude Code**: `~/.claude/skills/industrial-sdlc/SKILL.md`
- **Codex**: `~/.agents/skills/industrial-sdlc/SKILL.md`
- **opencode**: `~/.config/opencode/skills/industrial-sdlc/SKILL.md`

## 使用方法

当您需要从零开始构建大型项目时，直接提出需求即可触发本 Skill：

```
帮我做一个可以分析超大规模文档的 agent 平台
```

Skill 将自动：
1. 与您交互澄清需求
2. 进行多轮技术搜索
3. 产出 PRD 和最优技术方案
4. 等待您确认后进入设计阶段

## 红线规则

1. Phase 0 未完成 → 禁止进入 Phase 1
2. Phase 1 未完成 → 禁止写任何业务代码
3. 没有 API 文档 → 禁止开发接口
4. 没有表结构设计 → 禁止操作数据库
5. 没有用户确认 → 禁止进入下一阶段
6. 任何阶段禁止"先简单实现再升级"
7. 禁止使用 TODO/FIXME 占位符代替完整实现
8. 阶段完成后必须 STOP，禁止自动推进
9. **不考虑资源消耗，以最优方案为唯一目标**
